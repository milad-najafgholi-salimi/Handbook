در پایتون **Abstraction (انتزاع)** یعنی این‌که **یک رابط (interface) ساده و قابل‌استفاده ارائه بدی** و **جزئیات پیاده‌سازی را پشت آن پنهان کنی**؛ طوری که کاربر کلاس/ماژول فقط بداند _چه کارهایی می‌شود کرد_، نه این‌که _چطور انجام می‌شود_.

## چیکار می‌کنه؟

- **کاهش پیچیدگی:** با چند متد سطح‌بالا کار می‌کنی.
- **قرارداد مشخص می‌کند:** می‌گوید هر پیاده‌سازی باید چه متدهایی داشته باشد.
- **قابل تعویض بودن پیاده‌سازی‌ها:** می‌توانی چند کلاس مختلف داشته باشی که همگی یک “رابط” را رعایت می‌کنند.
- **امکان تغییر داخل بدون خراب کردن بیرون:** تا وقتی interface ثابت است، کد استفاده‌کننده تغییر نمی‌کند.

## چطور پیاده میشه؟

پایتون “interface” را معمولاً به دو روش رایج پیاده می‌کند:

### 1) Abstract Base Class (ABC) — روش رسمی و شفاف

با ماژول `abc` می‌گویی این یک «کلاس انتزاعی» است و بعضی متدها باید حتماً پیاده‌سازی شوند:
```
from abc import ABC, abstractmethod

class EmployeeBase(ABC): # inheritance
    @abstractmethod
    def calculate_salary(self):
        pass
```

حالا هر کلاسی که از این ارث ببرد **مجبور است** `calculate_salary` را بسازد:

```
class FullTimeEmployee(EmployeeBase): # inheritance
    def __init__(self, monthly):
        self.monthly = monthly

    def calculate_salary(self):
        return self.monthly
```

اگر پیاده‌سازی نکنی، پایتون اجازه ساختن شیء نمی‌دهد و خطا خواهد داد.

---
### 2) Duck Typing / Protocol-like — روش رایج پایتونی

در پایتون خیلی وقت‌ها لازم نیست رسماً ABC بنویسی. می‌گویی:

“اگر چیزی متد `calculate_salary` دارد، برای من مثل Employee است.”
```
def pay(employee):
    return employee.calculate_salary()
```

اینجا هر چیزی که `calculate_salary()` داشته باشد کار می‌کند، حتی اگر از کلاس خاصی ارث نبرده باشد. این هم نوعی abstraction است (رابط رفتاری).

---
## یک مثال خیلی ملموس از Abstraction

وقتی می‌نویسی:
```
f = open("a.txt")
text = f.read()
```
تو فقط می‌دانی “فایل باز شد و خوانده شد”، ولی جزئیات سیستم‌عامل، بافرینگ، هندل فایل و… پنهان است. این abstraction است.
